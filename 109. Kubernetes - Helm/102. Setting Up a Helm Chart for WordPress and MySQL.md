# Setting Up a Helm Chart for WordPress and MySQL

## Objective:
The DevOps team needs to deploy a multi-component application (WordPress connected to a MySQL database) using a parent/wrapper Helm chart for centralized management.
A known constraint is that the database sub-chart uses a deprecated image that requires a specific repository override to succeed.

### TASK - 1: Chart Initialization and Dependency Management

Initialize a new Helm chart named myapp that acts as a wrapper. Configure this wrapper chart to use the following external software components as dependencies (sub-charts) from the Bitnami Helm
repository, which is located at: https://charts.bitnami.com/bitnami.

  - mysql
  - wordpress

Selecting the Correct Sub-Chart Versions (IMPORTANT)

Before adding dependencies to Chart.yaml, you must determine the latest available chart versions from the Bitnami repository using:
```
helm search repo bitnami/mysql
helm search repo bitnami/wordpress
```

When you initialize a new Helm chart, Helm generates **default templates** for Deployments, Services, Ingress, HPA, and ServiceAccounts.

Since this is a **wrapper chart** (only managing sub-charts), these templates are not used and will cause **rendering errors**. Therefore, you must delete all default templates 
under: myapp/templates/ except _helpers.tpl.

### TASK - 2: Configure Custom Application Settings in values.yaml

Modify the values.yaml file within the myapp wrapper chart to inject specific, required configuration parameters into the sub-charts.

**WordPress Application and Database Connection Requirements (wordpress sub-chart):**

---

|   Parameter                   |  Value               |  Purpose                                                                  
| ----------------------------- | -------------------- | ----------------------------------------------------------------- 
|   wordpressUsername           |  "admin"             | WordPress administrator username.                                          
|   wordpressPassword           |  "adminpassword"     | WordPress administrator password.                                          
|   wordpressEmail              |  "user@example.com"  | WordPress administrator email.                                             
|   wordpressBlogName           |  "My Blog"           | Title for the WordPress site.                                              
|   externalDatabase.host       |  "myapp-mysql"       | The internal Kubernetes service name for the MySQL dependency.             
|   externalDatabase.user       |  "wp_user"           | Must match the configured MySQL username.                                  
|   externalDatabase.password   |  "wp_password"       | Must match the configured MySQL user password.                             
|   externalDatabase.database   |  "wordpress_db"      | Must match the configured MySQL database name.                             
|   service.type                |  "ClusterIP"         | Configures the WordPress svc to be accessible only within the cluster.

### TASK - 3: Deployment and Verification

  - Use the appropriate command to deploy the myapp wrapper chart using your local chart files.

  - Verify the deployment status of the Kubernetes Pods created by the mysql and wordpress sub-charts, ensuring they are running and using the specified custom values.
