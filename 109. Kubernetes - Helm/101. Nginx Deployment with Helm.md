# Nginx Deployment with Helm

## Objective
In this lab, you will deploy an nginx application on a Kubernetes cluster using Helm for package management. You will create a Helm chart named nginx, configure it to use the nginx:latest Docker image, and deploy it as a Helm release named nginx-deployment.

### Tasks
1. Initialize the Helm Chart

  - Create a Helm Chart

  - Begin by initializing a new Helm chart named nginx. This will automatically create a directory structure containing configuration files such as Chart.yaml, values.yaml, and a templates/ folder with deployment manifests.

  - Verify that the Helm chart folder (nginx/) and its key files (Chart.yaml, values.yaml, and templates/deployment.yaml) are created successfully.
  
  - Configure the Chart Metadata

  - Open the Chart.yaml file and ensure it contains the chart’s name (nginx), version, and a short description.

  - This file defines the chart metadata required by Helm for packaging and deployment.

  - Modify Application Configuration

  - In the "values.yaml" file, locate the section defining the container image.

  - The repository is already set to nginx; update the image tag to "latest".

  - This ensures Helm pulls the most recent nginx image version during deployment.

2. Deploy the Application

  - Deploy Using Helm

  - Use Helm to install and deploy the chart to the Kubernetes cluster.

  - The release name should be "nginx-deployment" and it should deploy resources defined in your nginx/ chart directory.

  - Verify Deployment Status

  - Once deployed, ensure the deployment named nginx-deployment appears in the cluster.

  - Confirm that its status is Available and the pods are running successfully.

### Notes

  - The filenames and directory structure created by the helm create command must remain intact.

  - Do not rename or move files outside the nginx/ folder.

  - The image tag must be "latest" to pass the configuration test.

  - The Helm release must be installed with the name nginx-deployment.
