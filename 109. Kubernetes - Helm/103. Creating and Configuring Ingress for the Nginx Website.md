# Creating and Configuring Ingress for the Nginx Website

## Objective
You are tasked with creating a Helm chart to deploy an Nginx web application, configure an Ingress to expose it using a custom hostname, and serve a “Hello World” webpage using a ConfigMap.

In this assignment, we will practice **Helm chart customization, Kubernetes Ingress routing, and ConfigMap-based static content delivery, and versioning Helm charts after updates.**

## Instructions

### 1. Create the Helm Chart

  - Create a new Helm chart named nginx-website.

  - Ensure the chart structure includes: Chart.yaml, values.yaml , templates/ directory

### 2. Update values.yaml with Required Configurations

Deployment:

replicaCount: 1

Image settings:

repository: nginx

tag: latest

pullPolicy: IfNotPresent

Service:

Type should be ClusterIP

Port should be 80

Ingress:

Enable Ingress

Use hostname: nginx.example.com

Add a path / with ImplementationSpecific as pathType

Include the annotation: nginx.ingress.kubernetes.io/rewrite-target: /

Volume + ConfigMap Mounting:

Define a volume named html that uses a ConfigMap

Mount that volume to /usr/share/nginx/html inside the Nginx container

Note: You will create the ConfigMap in the next step — ensure the volume references match.

### 3. Create a ConfigMap to Serve HTML Content

In templates/, create a ConfigMap named hello-world-html-cm

It must contain an index.html file under .data that displays a basic “Hello, World!” webpage

### 4. Deploy the Helm Chart

Install the chart using a release name nginx-website

Command should be executed from the directory where the chart exists

### 5. Test the Ingress

Verify the Ingress object was created using kubectl commands.

Add the hostname to your machine's /etc/hosts file and access the application

Ensure the “Hello World” page from your ConfigMap is displayed

### 6. Update Chart Version (Post Deployment)

After successful deployment and testing:

Open Chart.yaml

Increase the version: field (e.g., from 0.1.0 to 0.1.1)

Save the file to reflect that your chart has been modified and validated.

Then apply this updated version to the existing release. This updates the release to use the new chart version.

Helm will record this as a new revision (you can verify using helm history nginx-website)

## Important Notes
An Ingress Controller (e.g., NGINX Ingress) must already be installed in the cluster.

Keep naming consistent — chart name, ConfigMap name, volume name, and mount path must match exactly as stated.

YAML indentation and directory structure under Helm must be accurate.

Do not use pre-built charts — work only within your own nginx-website chart.

## Outcome
By completing this task, you will:

Create and customize a Helm chart for Nginx

Configure an Ingress to expose the application via hostname

Serve static HTML content using ConfigMap and volume mounts

Successfully access the application using http://nginx.example.com
